# Přejeme si — What This Is

Přejeme si is a shareable wishlist web app where users create gift lists for themselves or someone else and share them with friends and family. Ordinary recipients are protected from reservation spoilers; explicitly disclosed self-promotion and the narrow deletion-grace exception are defined in [DECISIONS.md](DECISIONS.md). Built with SvelteKit, Tailwind CSS, Drizzle ORM + PostgreSQL.

## Domain Language

### Roles and core objects

- **Wishlist** — A collection of desired gifts for a recipient, managed by a linked recipient and/or správci. An occasion wishlist may be ongoing (no date) or tied to a specific occasion; a permanent wishlist never has an event date.
- **Gift** — An item on a wishlist with name, optional description/URL/price/image/priority/quantity.
- **Recipient (obdarovaný)** — The person a wishlist is for: a linked user or a free-text name (e.g. a child); linked recipients manage their lists but cannot reserve, and see reservation state/counts only after disclosed self-promotion, never gifter identities. A linked recipient may change their own list to a free-text recipient, becoming a normal správce.
- **Správce (manager)** — User with full management rights plus full visibility (reservations, gifter identities); can reserve gifts and manage other správci. Code role: `moderator`.
- **Admin** — App operator matched via `ADMIN_EMAILS` env var; the only role that can revert a reserved shared list to draft, and the only one that can release a SIGNED-IN gifter's single reservation (issue #213). Not a správce, never surfaces in list UI.
- **Visitor** — Anyone viewing a wishlist via a shared link; can reserve, unreserve, and like gifts.
- **Gifter** — A visitor who has reserved at least one gift on a wishlist.
- **Reservation** — A claim on one or more units of a gift by a visitor; prevents duplicate buying.
- **Like** — A persistent interest indicator on a gift; triggers notification if someone else reserves it.
- **Claim link** — Token link („Pozvat obdarovaného") generated by a správce so a free-text recipient's real account can claim the list: links the account, strips reservation state, shows it in their Moje seznamy.

### Sharing and lifecycle

- **Sharing** — Distributing a wishlist link. Freezes each existing gift's identity (`name`) and blocks delete, but leaves presentation/info fields editable (image, links, price, priority, append-only description; quantity raise-only). On a permanent wishlist this applies only to reserved gifts. See Post-share editing.
- **Occasion wishlist** — The default wishlist kind, with or without an event date; sharing applies the strict post-share gift rules to every gift.
- **Permanent wishlist** — A wishlist kind chosen at creation for a list that changes over time: no event date, and after sharing its unreserved gifts stay fully editable and deletable. It can become an occasion wishlist any time; an occasion wishlist becomes permanent only before it is first shared.
- **Post-share grace window** — A 2-minute reversibility window for sharing, each description append, and the event-date lock; later gift edits never reopen gift name/delete grace.
- **Description append** — A post-share description change: an immutable, accent-colored, timestamped addition. The original text freezes at share time and is preserved for the gifter; Card/List previews show only the latest append; full history remains available in detail and editors.
- **Archive** — A read-only state for a completed wishlist; visually distinct, no new reservations accepted.
- **Unfollowed** — A wishlist the user was previously invited to / followed but has since unfollowed. Tracked for re-discovery via toggle on the Sledované page.

### Gift entry and display

- **Gift draft** — An unsaved, editable gift row (name, notes, link(s), price) in the import or batch grid, before it is committed as a real Gift.
- **Draft grid** — The editable multi-row table that powers both the import Review step and batch gift entry; each row is a Gift draft.
- **Import wizard** — The 3-step Source → Review → Confirm flow that turns a pasted/uploaded CSV or Google Sheet into gifts.
- **Batch add** — Adding multiple gifts at once via the shared draft grid (distinct from the import wizard, which sources data externally).
- **Enrichment** — Auto-filling a gift's image / price / title from its link (and, in a later phase, by searching for it by name).
- **Multi-link** — Multiple URLs attached to a single gift (up to 10); `links[0]` is treated as the primary link.
- **Piece count** — Gift quantity; ordinary recipients see quantity without reserved counts, while disclosed self-promotion and other role capabilities govern reservation visibility.
- **Gift viewer** — The read-only, photo-first gift detail with a caption and the viewer's applicable actions; managers get the gift editor instead.

### Images

- **ImageFrame** — The single shared image renderer used for all fixed-size image boxes (gift cards, wishlist cards, avatars). Handles fit mode and focal-point crop consistently across surfaces.
- **Fit mode** — The persisted ImageFrame mode: legacy heuristic `auto`, letterboxed `contain-padded`, or focal/zoom-based `cover-crop`; editors offer Fill/Fit/Manual instead of `auto`, and may present measured legacy images as Fit without dirtying the form or rewriting untouched metadata.
- **Image editor mode** — The user-facing three-mode model in the gift/wishlist image editors (#116 follow-up): Fill („Vyplnit", automatic centered cover), Fit („Přizpůsobit", letterboxed), Manual („Ručně", user-drawn per-target/per-slot crops). Maps onto persisted fit modes via `editor_modes.ts`; Fill and Manual both persist `cover-crop`. Clicking a preview tile or wheel-zooming a plain preview promotes to Manual — the tiles are the only crop-target switcher (round 3 removed the per-target radio picker). Manual zoom ranges from the target's contain zoom (whole image, one-axis letterbox) up to 300 %. In the gift modal the mode toggle sits in the image column above an adaptive crop stage that shows the WHOLE photo contained (portrait tall, landscape wide, within min/max caps) with the active target's window overlaid — overhang dimmed, never clipped at default zoom (issue #189). Two switcher tiles sit with the stage: „Karta" (4:3 = `square` target) and „Seznam a rezervace" (1:1 = `thumb` target); they are the only crop-target switcher, and clicking one jumps to Manual with that target active.
- **Focal point** — A persisted `{ x, y, zoom }` triple (x/y in percent 0–100, zoom from the per-aspect contain zoom up to 3) that is the canonical crop representation consumed by the renderer. Zooms below 1 (#116 round 2) letterbox the image inside the frame on exactly one axis. Resolution- and aspect-ratio-independent.
- **Crop rect** — A normalized editing rectangle persisted alongside focal point so the crop editor can restore the exact region the user drew. Since issue #116 it is always locked to its target's aspect ratio, making the focal+zoom render a lossless reproduction; since round 2 it may extend past the image (size > 1, negative origin) on ONE axis for zoomed-out letterbox framings — invariant `min(w, h) ≤ 1`. Not used for rendering — focal point is.
- **Crop target** — A gift consumer surface group by aspect family. Two ACTIVE, editor-offered targets (issue #189): `square` (4:3 gift-card-grid family — the name stays `square` for backward-compatible persistence despite the aspect no longer being square, issue #183) and `thumb` (true 1:1 — the reservation-modal thumb and the saved square List composition; full-height mobile List frames and taller desktop List frames show a portrait side-window of that composition). Plus two retired legacy fallbacks kept only to parse old rows: `card` (~2.78:1) and `detail` (~0.5 — the **Gift viewer** now shows the uncropped photo instead, see below). The 1:1 `thumb` reads `targets.thumb ?? targets.square` and reprojects the same focal+zoom at render time, so pre-#183 crops carry over with no migration. Manual crops persist per target in `image_meta.targets`; targets without one keep automatic center cover-fit framing. Aspect specs live in `crop_targets.ts` (single source for editor stage, previews, and e2e asserts). The **Gift viewer** is NOT a crop-target consumer — it renders the full photo at its natural aspect ratio inside a height cap.
- **Image slot** — A named display position on a wishlist: `card` (dashboard banner ~2.84:1), `thumbnail` (1:1 — header polaroid, nav, list rows), or `social` (1.91:1 OG preview). Each slot carries its own independent crop metadata (`image_slots` JSON column). The legacy `banner` slot is retired from the editor (persisted JSON retained).
- **Image-frame fill** — The independently selected background behind letterboxed images, including white, black, or the default transparent/dotted mat.

### Appearance

- **Palette** — A curated color identity used for both a user's app appearance and an independently chosen wishlist appearance; available choices are defined in `src/lib/theme/palettes.ts`.
- **App palette** — A per-user appearance preference mirrored in a cookie and applied as SSR `data-palette` on `<html>`; the old app-background theme axis is retired.
- **Scoped wishlist palette** — Palette-derived semantic tokens applied on the wishlist subtree without changing the viewer's app-shell palette.
- **Palette derivation** — Curated primitives derive semantic colors through CSS `color-mix(in oklab, …)`; arbitrary category-picker hex colors are not custom wishlist palettes.

### Navigation

- **Přehled** — The logged-in home page at `/home`: horizontal carousel rows (Nedávné, Sledované, Spravované, Moje seznamy). Target of `/`, the post-login default, and the logo; in the mobile drawer but not the desktop nav.
- **Nedávné** — The top Přehled row: wishlists across all roles sorted by last visit (via `lastVisitedAt` upserted on logged-in wishlist visits), follow-date fallback, not deduped from the category rows.

### Agent access

- **Access token** — A user-created, scoped and revocable credential that lets an agent act as that user.
- **Proposal** — A stored batch of agent changes, checked with a dry-run, that the user reviews and applies on the preview page.
- **Fast-forward** — A per-token or per-chat setting that applies proposals without the visual review, never for deletions, reservations or manager invitations.
- **Gift revision** — A before/after record of one gift change, with who made it and how, used for history and Undo.

_Avoid_: "list" for Wishlist (ambiguous), "present" for Gift (confusing with time), "bookmark" for Like, "claim" for Reservation.

## Features

### Done

- Accounts: email/password with optional Google sign-in; anonymous visitors with a display name and optional email.
- Wishlists: create, edit, share, archive, revert to draft (správce when reservation-free, admin when reserved); lists for someone else with claim links and recipient reassignment.
- Gifts: add, edit, remove, reorder, up to 10 links, image fit/crop, categories with priority/category grouping and facets, mark as received.
- Bulk entry: shared draft grid and the CSV / Google Sheets import wizard.
- Reservations with quantity support, single-reservation release, and likes.
- Roles and privacy: recipient, správce, visitor, admin; recipient surprise protection and post-share edit rules.
- Sharing: visitor links, manager invites, social buttons.
- Notifications: critical email, in-app activity, new-gift digest.
- Navigation: Přehled home and the Moje seznamy, Spravované and Sledované section pages.
- Appearance and language: curated user and wishlist palettes, image-frame fill, Czech primary with English.
- Profile and settings: identity, notifications, appearance.
- Isolated editable demo playground from the landing page.
- Production gift ingestion (allowlisted manifest API and CLI), interim until [#476](https://github.com/MartinoPolo/prejemesi/issues/476).

### Planned
