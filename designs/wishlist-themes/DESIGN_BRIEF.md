# Design brief: wishlist themes (#535)

Managers can personalize a wishlist beyond its palette with themed decorative backgrounds, a personal background image and a small set of wishlist-scoped style tokens. App chrome (header, navigation, dialogs, menus) keeps the viewer's Přejeme si palette and brand shape. Research: `RESEARCH.md`. Mockups: `index.html` (generated by `build/build.mjs`).

## Theme model

**Theme = palette + background layer + decorative motif set + default style tokens.** A theme is a curated preset, not a separate rendering system.

| Layer | Source | Scope |
| --- | --- | --- |
| Palette | Existing curated registry (`src/lib/theme/palettes.ts`, `data-palette` on the wishlist wrapper) | Wishlist subtree |
| Background | Theme pattern + illustrations, a custom upload, or none | Behind the wishlist subtree only (`z-index: -1` layer inside the wrapper) |
| Motifs | Inline SVG illustrations tinted through art variables (`--m-a…--m-d`, `--m-ink`) | Desktop side gutters; mobile top strip |
| Style tokens | `data-corners`, `data-border`, `data-mat`, `data-heading` on the same wrapper | Wishlist subtree |

- Choosing a theme sets the palette, background and token defaults. Each part can then be overridden, and “Obnovit styl podle motivu” restores the theme defaults. Persist the overrides separately from `theme_id`, so a later redesign of a theme does not overwrite choices the user made explicitly.
- Every visitor sees the wishlist's theme. The viewer's own palette, light/dark mode and **shadow depth** preference still apply.
- Suggested additive schema: `wishlists.theme` (nullable text, theme registry key), `wishlists.style` (nullable JSON of overridden tokens) and `wishlists.background` (nullable JSON: `{ mode: 'theme' | 'custom' | 'none', imageKey, focal: { x, y }, placement: 'gutters' | 'full', dim, motion: 'subtle' | 'off' }`). A null value keeps today's look, so no row migration is needed.

## Recommended user-exposed tokens

| Token | Options (default first) | Why expose it |
| --- | --- | --- |
| **Rohy** (corner shape) | Zaoblené 16/7 px · Jemné 8/4 px · Ostré 0 | This was the owner's explicit ask, and the shape changes the mood more than anything else short of color. It maps onto `--radius-panel`/`--radius-btn`/chip radius. Nested radii keep following the `AGENTS.md` rule, so they never need a separate control. |
| **Okraje karet** (border weight) | Výrazné 2 px · Jemné 1 px | The ink outline stays (it is the brand's identity), but a fine line suits the wedding, books and minimal themes. Only the weight changes, never the color. |
| **Rámeček obrázků** (image mat) | Tečkovaný · Bílý · Černý | This reuses the existing image-frame fill choice (DECISIONS 2026-08-26) as the wishlist default. Dark mats suit gamer lists, and white suits product photos. |
| **Písmo nadpisů** (heading font) | Hravé (DynaPuff) · Elegantní (Fraunces) · Střídmé (Geist) · Ručně psané (Caveat) | Fonts are suitable when the set is curated. Each family needs Czech glyph coverage, self-hosting, a metric-adjusted fallback and loading only on lists that use it. The font applies to the wishlist title, group headings and gift titles. **Ručně psané is limited to the title and group headings**, and gift titles fall back to Geist for legibility. |
| **Pozadí** (background) | Z motivu · Vlastní obrázek · Žádné | This is the core of #535 (see below). |
| **Pohyb při posouvání** (scroll motion) | Jemný · Žádný | Lets managers opt out of motion. The OS reduced-motion setting always wins. |

### Brand-locked (not exposed)

- **Text and label colors.** They derive from the palette so that the AA guarantees (`palette_contrast.svelte.test.ts`, DECISIONS 2026-10-17) hold for every combination. A free text-color picker would break those guarantees, and the matching surfaces are already themed through the palette.
- **Shadow depth/style.** DECISIONS 2026-09-12 makes it a viewer preference. Exposing it per wishlist would contradict that decision and the depth-clearance spacing rules.
- **Body font (Geist), control heights, spacing and motion timing**, plus status colors (reserved, received, danger) and the app header, navigation, dialogs and menus. These keep the product recognizable and its controls predictable.

## Backgrounds

**Desktop (gutters ≥ 1260 px container).** The live content container (1120 px plus gutters) leaves side gutters, and the background fills them. The theme layer is a CSS pattern plus 8 motifs per side at three depths (far, mid, near), placed deterministically. A soft center wash sits behind the content column. Content surfaces (notebook, toolbar, group plates and gift cards) stay opaque paper, so text never sits on artwork. On the dark-backdrop themes (Herní doupě, Vánoce, custom photo), the hard shadow switches to black for separation.

**Tablet and mobile.** Gutters are only 12–16 px, so the motifs move to a short strip (about 64–84 px) above the notebook header, and the theme pattern shows faintly between cards. The strip scrolls away with the page. It is decoration, not the full-bleed hero that DECISIONS 2026-07-10 forbids.

**Custom upload.** The upload goes through the existing image pipeline (R2, one `image_key`, server-generated widths of roughly 800 and 1920 px in WebP or AVIF). Controls:

- A focal point, which drives the mobile strip crop and the desktop anchoring.
- Placement: **Po stranách** (default) shows the photo in the gutters with a strong center wash. **Celá plocha** shows the photo across the page under a dim layer.
- Ztlumení (dim, 0–60 %).

Because content stays on opaque paper, contrast never depends on the photo. Dim is aesthetic, plus an automatic minimum for very busy or high-contrast images (state 4 in `customize.html`). Uploads follow the same size and type limits as gift images.

## Motion

- One effect: decorations drift vertically at depth-dependent rates while the page scrolls (parallax). The custom photo is a sticky layer that drifts by about 50 px over the whole scroll.
- Implement it with CSS scroll-driven animations (`animation-timeline: scroll()`), animating only `translate`. No scroll listeners and no layout work. Browsers without support show the background statically, which is acceptable.
- Gate it with `@media (prefers-reduced-motion: no-preference)` and the per-wishlist “Žádný” setting. The mockups verify both paths: the translate changes while scrolling and is `none` under reduced motion.
- Mobile performance: limit motifs to the strip, use inline SVG without filters on low-end devices (the decorative drop-shadow can be baked into the SVG), and serve the custom photo at viewport width. Do not use `background-attachment: fixed`, because it repaints on iOS.

## Open questions (with recommendations)

1. **How many themes at launch?** Recommendation: ship the ten shown and grow by occasion demand. Curation over volume is the point.
2. **Should a theme also apply to the polaroid placeholder and the OG/social image?** Recommendation: yes for the placeholder (show a theme motif when there is no image). Defer the OG image to a separate issue.
3. **Dark mode for light themes?** Recommendation: derive a dark backdrop by mixing the theme backdrop toward the dark-palette charcoal and keep the motifs at full color. The dark-native themes (Herní doupě, Vánoce) look the same in both modes.
4. **Who can pick a theme: recipient, správci or both?** Recommendation: the same roles that can change the palette today. The theme belongs to the wishlist settings draft and the global Save.
5. **Should custom uploads be moderated?** Recommendation: treat them like gift and wishlist images (same limits and reporting). No pre-moderation.
6. **Should the theme be offered in the quick-create modal?** Recommendation: no. Keep creation quick (DECISIONS 2026-05-30), but default the theme by occasion when the title or date implies one (for example December leads to Vánoce), and let the manager change it in Settings.
7. **Should text-heavy views (List, Compact) keep the gutters?** Recommendation: yes. The gutters are outside the content container, so view density is unaffected.
8. **Does the image-mat token replace the per-image fill?** Recommendation: it sets the wishlist default, and an explicit per-image fill (if one exists) still wins.
9. **Should Ručně psané (Caveat) be kept?** Recommendation: keep it, limited to titles. If Czech diacritics render poorly at small sizes after font QA, drop it rather than widening its use.
